> Depth layer: a database of one card per alternative, not exported to the mirror, pending ratification.

## How this page works

This is a thin canon page over a depth database. The page holds the summary table and the rules; each card (tier, status, last-updated, dated CRM snapshot, evidence) is a row in the Battlecards database behind it. Repo-grounded agents receive this page and a pointer; agents with the knowledge-base connector query the cards live. If a card conflicts with this page, this page wins.

## Refresh rules (the propose path)

- Monthly, an agent refreshes each card's CRM snapshot with an as-of date, appends dated and cited evidence, and tags new unconfirmed claims [verify]. It supersedes rather than deletes.
- Status changes, tier moves, retirements and any edit to the table above are **proposed only**. The agent proposes; the owner verifies.
